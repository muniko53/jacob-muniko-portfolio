Services

Work that has to hold up after handover.

I take on a small number of projects at a time. Each one starts with the constraint and ends with something you can run, understand, and maintain. I am an independent builder, not an agency.

Web development

Sites, applications, interfaces

I build web applications where the interface, the data, and the account system all have to agree. That includes marketing sites that need a real content structure, product MVPs, dashboards, and the front end of an existing system that has outgrown its first version.

Problems I can help with

  • A product idea that needs a working first version, not a slide deck.
  • A site that is hard to update, slow on a phone, or invisible to search.
  • An interface that works in a demo but breaks under real data.
  • A front end that needs to connect to an API, auth, or payments.

Typical deliverables

  • Responsive React or server-rendered pages.
  • Authentication, roles, and protected routes.
  • REST APIs and database models.
  • Deployment to Vercel, Cloud Run, or a static host.

AI development

Assistants, integrations, guardrails

Most useful AI work is narrow. I build assistants and model-backed workflows around a specific job, with clear boundaries around what the model can read, what it can change, and what happens when a provider fails or a quota runs out.

Problems I can help with

  • A workflow where a model could remove repetitive reading or drafting.
  • An assistant that needs access to files, tools, or a research step.
  • A prototype that needs honest failure states and cost controls.
  • A local-first tool where private data should stay on the machine.

Typical deliverables

  • Provider integration with fallback and quota handling.
  • Tool calling with an approval gate for consequential actions.
  • Prompt and evaluation harnesses for a narrow task.
  • Local-first desktop or browser interfaces.

Workflow automation

Pipelines, reports, integrations

If a process happens the same way every week, it can usually be made smaller. I connect the sources, clean the data, generate the report, and deliver it where people already work. The important part is not the automation itself. It is knowing what should happen when a source fails.

Problems I can help with

  • A report assembled by hand from several websites or spreadsheets.
  • Data that arrives in different shapes and needs one reliable format.
  • A scheduled task that breaks silently when a source changes.
  • Repetitive messages, updates, or follow-ups that need a trigger.

Typical deliverables

  • Scheduled GitHub Actions or n8n workflows.
  • Source isolation with visible failure states.
  • HTML, CSV, or Excel reports delivered by email.
  • API integrations with documented secrets handling.

Custom software

Desktop tools, internal utilities

Some work does not belong in a browser. I build focused desktop utilities and internal tools for file-heavy, local, or Windows-specific jobs, with a safety layer around anything that can move or delete a file.

Problems I can help with

  • Storage, duplicates, or file organisation that no off-the-shelf tool handles well.

Typical deliverables

How it works

Four steps, no theatre.

Small projects move quickly. Larger ones get a written scope before code starts.

  1. Conversation

    You describe the problem, the people, and the deadline. I ask the questions that change the shape of the build.

  2. Scope

    We agree on the smallest complete version, what is explicitly out of scope, and how we will know it works.

  3. Build

    I work in small, testable increments and keep you able to see progress. Decisions that affect the product are written down.

  4. Handover

    You get the source, setup notes, and a walkthrough. If something is still uncertain, it is listed as uncertain rather than hidden.

Honest boundaries

What I am not.

I am strongest in React and TypeScript, Node.js, Python, PostgreSQL, browser interfaces, and workflow automation. I have built and tested a Windows desktop application in PySide6, and I work on local-first AI systems with explicit approval gates.

I am not a native mobile specialist, a machine-learning researcher, or a large delivery team. If your project needs one of those, I will say so instead of stretching the scope.

I do not publish client names, revenue figures, or testimonials I cannot verify. This site is a record of work I can show, not a sales deck.

Pricing is per project and by enquiry. I quote after the scope conversation so the number reflects the work rather than a package.
