The constraint

A full drive is easy to see and hard to understand.

Windows Explorer will tell you a folder is large. It will not tell you why, which copies are identical, what is safe to remove, or what will happen if you remove it. Most cleaner tools answer those questions by making the decision for you: pre-selected files, a permanent delete, an opaque score, or a cloud account.

FilePilot started from a practical annoyance: a C: drive with no room left and no clear answer about what was using it. The constraint was not “scan faster.” It was “be useful without being dangerous.” Every action had to be explainable before it happened, reversible where possible, and verified again at the moment it ran.

The system

A local desktop tool with a read-only first half.

FilePilot is a PySide6 desktop application backed by SQLite. The scanner walks with os.scandir, never reads file contents, and streams results into SQLite in bounded batches. Links and junctions are never followed. The UI is thin; the logic lives in a Qt-free core so it can be tested without a window.

That split matters for a file tool. A long scan cannot block the interface, and a destructive action cannot live only in a button handler. Slow work runs in a worker thread and reports progress, cancellation, and failure through signals. The safety rules are ordinary code with tests, not a warning label.

What it does

From “what is using the disk” to “remove this copy”

  • Storage analysis. Background scan with cancel, a lazy folder tree, treemap, paged file table, filters, file types, and issues.
  • Storage analytics. Compare saved scans of the same folder to see growth or shrinkage by folder.
  • Search and preview. Search the loaded scan and read size-bounded previews of text, images, PDF and Word facts, and ZIP listings. Archives are never extracted.
  • Exact duplicates. SHA-256 verification, hard-link awareness, a suggested copy to keep, and a review step that re-reads every file before removal.
  • Smart Clean. A read-only scan of temp files, crash dumps, package-manager and browser caches, inactive node_modules, and the Recycle Bin. Nothing is pre-selected.
  • Organiser and operations. Organise by type, month, or year; batch rename with preview; folder comparison; one-way sync that copies missing files and never overwrites; undo.
  • Safe deletion. Plan, review dialog, approval bound to that exact plan, per-item revalidation, audited result, and the Recycle Bin by default.
  • Security Centre. Reports Microsoft Defender's status, starts scans, and shows threat history. FilePilot does not pretend to be an antivirus.
  • Diagnostics and recovery. Nine read-only Explorer checks, plus a guided recovery walk-through that builds a Windows File Recovery command for you to run yourself.
  • Backup Assistant. Checks for backup evidence and builds an approval-gated, one-way copy plan.

Decisions that mattered

Safety is a sequence, not a setting

Read-only before write
Scanning, duplicate detection, Smart Clean, diagnostics, and recovery all produce evidence before they offer an action. Smart Clean deliberately pre-selects nothing. The user chooses every item.
Approval bound to a plan
A deletion is planned first. The review dialog shows the effect, and the approval is tied to that exact plan. At execution, each item is revalidated by identity, and a mismatch stops the operation. If the Recycle Bin fails, it does not silently fall back to permanent deletion.
Links and junctions are never followed
A scanner that follows links can escape the folder it was pointed at or count the same file twice. FilePilot skips them and lists them separately. OneDrive-style reparse points are treated as cloud folders, not links, so those folders still scan.
Scan status has meaning
A scan is complete only when the walk finishes. Cancelled is partial and labelled. A disconnected drive or internal error is failed. History and the dashboard use the same vocabulary, so a partial scan cannot quietly become a total.
Migrations are tested at every version
SQLite migrations are versioned and transactional. A failed migration rolls back; a newer schema is refused. The test suite opens databases as older versions would have left them, including an interrupted upgrade.
Local by default
No accounts, telemetry, or analytics. The only network use is an optional button that runs pip for a PDF or Word parser when running from source. It does nothing until the user clicks it.

What I built

Every layer, including the unglamorous ones

I built FilePilot end to end: the scanner and SQLite schema, the safety and operations modules, the duplicate verifier, the worker layer, every page of the PySide6 interface, the approval dialog, the localization catalogue, the packaging scripts, and the test suite. The project is solo work.

The engineering value is in the parts that are easy to skip: a scan that streams instead of loading a tree into memory, a CSV export that resists formula injection, an approval that cannot be reused for a different plan, and an audit trail that says what actually happened. The current release is 0.20.0 beta.

Status

Beta, with the Windows gaps named

Beta

Version 0.20.0. The core is covered by 491 automated tests, including offscreen GUI tests and mutation checks on the safety rules. The scanner, long paths, junction detection, drive discovery, and icon fonts have been confirmed on a real Windows 11 machine.

Not yet verified on Windows: Recycle Bin and shell calls, the Defender integration, the Explorer diagnostics and recovery internals, and the installer. No prebuilt installer is published yet, and the installer is unsigned. A Narrator/NVDA audit and 150%/200% display-scaling check are still to do.

Performance was measured honestly: 100,000 synthetic files scanned in 1.2 seconds on Linux, and a real Windows scan of about 1 million files took 3 minutes 16 seconds. Linux results are not Windows verification.
